# Anvil project review — 2026-09-05

> **Status (end of 2026-09-05):** every finding below was addressed in versions 2.0.0 to 2.3.3, see `CHANGELOG.md`. Refuted, opinion-only and Windows-only template items were handled by the removal of the Grok scaffolding. The verification tooling lives under `tools/` and is documented in the README.

## Executive summary

**Verdict.** The browser studio renders and the HTTP MCP endpoint answers every method correctly, but the product's core promise, a working Blender round-trip driven from Claude Code, is broken at five independent points, and much of what the tools and panels report (dimensions, QC, naming, engine) is not what the code actually produces. None of the generated Blender scripts has ever run: every build script is a Python syntax error, and once dedented it crashes on an API removed in Blender 4.1. The local stdio MCP server speaks the wrong wire framing, so Claude Code can never initialise it. The persisted library is wiped on every reload. The preview renders models near-black because albedo and roughness are applied twice. The art-direct server function is a public, unmetered proxy to the owner's xAI key (moot, since xAI integration is being removed).

**How this was produced.** Toolchain runs on this machine (typecheck, lint, tests, production build), a 15-agent workflow (7 finders with distinct lenses, 7 adversarial verifiers that re-derived and re-executed every claim, 1 completeness critic; 544 tool calls), plus a headless check with the Blender 5.2.1 LTS that was installed today. Only verifier-confirmed findings are listed below; cross-lens duplicates were folded; one finding was refuted and is listed as such.

## Three buckets

**Wrong** (would fail even if the build had finished; all proven by execution unless noted):
- Local stdio MCP server uses LSP Content-Length framing; MCP stdio is newline-delimited. Claude Code's initialize is never answered (local-01).
- Every generated build script fails to compile (indented material block, blender-py-01); dedented, it dies on `use_auto_smooth`, removed in Blender 4.1 (blender-py-02); the emissive block references an undefined variable (blender-py-03).
- Persisted state is overwritten with defaults before it is read back, on every reload (react-viewport-02).
- Preview and GLB apply albedo and roughness twice and tag the roughness map sRGB: models render near-black and exports are far glossier than the Inspector says (react-viewport-03/04). Lit never restores after Clay/Wire/Unlit (react-viewport-01).
- Built geometry deviates more than 10% from the printed dimensions for 12 of 22 prototypes and floats or sinks for 9; the GLB has no engine naming, no collision, and the same filename for every LOD, while QC shows PASS (critic-builders-01, critic-export-01). QC itself is vacuous: 5 of 10 checks are hard-coded PASS (assets-pipeline-01).
- Kind and engine inference is ordered substring matching: the app's own catalog briefs misroute (Sidearm forges a barrel, "oil lantern" is a barrel), and brief text silently overrides an explicit engine (assets-spec-01/02/03).
- Blender add-on: auto-starts an unauthenticated exec-anything TCP server on every Blender launch (addon-04); job ids are memory addresses, so timed-out scripts hand their results to the next request (addon-01); 15 s client timeout vs ~25 s server poll loses every long result (addon-02); a self-rescheduling timer leaks per poll (addon-07).
- Generated scripts wipe the user's open scene first (blender-py-08); collision box is half size and floating (blender-py-04); pivot is never implemented (blender-py-06); unwrap angle passed in degrees is clamped to 90 (blender-py-05); the bake script bakes a flat normal into sRGB, unsaved images (blender-py-09).
- Remote MCP: GET stream held open forever instead of 405 (mcp-http-01); a throwing message turns into HTTP 500 and drops the whole batch (mcp-http-02); the remote `blender_execute` executes nothing while instructions and prompts say it does (local-04).
- Art-direct server function: unvalidated, unmetered, publicly callable (platform-01/02/03/04).

**Unfinished** (never got done before the build stopped):
- No tests for the MCP handler, tools, inference, naming, pipeline, builders or generated scripts (platform-09).
- Library load/remove actions have no UI callers; KIND_LABEL, allKinds, disposeTextures, set_origin_bottom are dead code (react-viewport-18 and critic notes).
- Docs and example config point at placeholder hosts and cwd-relative paths (local-03).

**Environment** (only bite because the project now lives on Windows outside the sandbox):
- `npm run dev/build/preview` fail: the env wrapper spawns `vite` without a shell (platform-06).
- `npm test` skips the script tests: single-quoted glob under cmd.exe (platform-07).
- A symlink test needs Developer Mode (platform-10). `startup.sh` hardcodes /workspace.
- All project files carry modification times about 3 hours in the future (export artifact); ignore mtimes.

**Refuted.** The concern that the add-on's timer context would break generated scripts was tested and does not hold (blender-py-14).

**Done well.** JSON-RPC error handling, batching and id handling are correct and were exercised live; the server is stateless and cheap; the UI layout is deliberate on desktop and mobile; the store's SSR pattern is right in principle; the domain model is cleanly separated from transport and UI.

### addon-04 — register() opens an unauthenticated exec-anything TCP server 0.8 s after the add-on is enabled and on every Blender launch thereafter, contrary to the documented 'press Connect' flow

## Critic overall assessment

Anvil is a TanStack Start/React 19 app that turns a text brief into a game-asset spec from 22 procedural prototypes and exposes that logic three ways: a three.js preview with GLB download, an HTTP MCP server with 11 tools/5 resources/3 prompts, and a Blender bridge (generated bpy scripts, a stdio MCP relay, a TCP add-on). What works today: the HTTP MCP endpoint answers every method and Claude Code can list and call the tools, the Studio renders and forges locally, and the naming/QC/pipeline text is mostly sensible. What does not work: every generated Blender build script is a Python syntax error and, once dedented, still aborts on a property removed in Blender 4.1 (blender-py-01/02/03); the shipped stdio relay uses Content-Length framing so Claude Code can never initialise it (local-01); persisted state is clobbered on every reload (react-viewport-02, which the rubric would call critical, not high); and the add-on auto-starts an unauthenticated exec-anything TCP server with job-id cross-talk and unbounded timer leaks (addon-01/04/07). The preview is less honest than its panels: albedo and roughness are applied twice, the built geometry is up to 42% smaller than the dimensions it prints, the LOD buttons show budgets 5-25x the real counts, and the GLB carries no engine naming or collision while QC displays PASS (critic-builders-01/02, critic-export-01). The top risks are cost and safety exposures (expandBrief as a public unmetered xAI proxy, platform-01; scene-wiping scripts with no warning, blender-py-08; the hold-open SSE GET on Vercel, mcp-http-01) followed by the credibility of tool output (substring kind/engine inference overriding explicit arguments, assets-spec-01/03; vacuous QC, assets-pipeline-01; kit tool contradicting itself, critic-tools-01). Fix first, in order: (1) blender-script.ts indentation, use_auto_smooth and the emissive `m` block, three small edits that make every script runnable; (2) newline-delimited framing in anvil-mcp-server.mjs; (3) rehydrate before the mount effect writes (or gate persist writes on hasHydrated) in Studio.tsx/store.ts; (4) rate-limit and validate expandBrief and return 405 on GET /api/mcp; (5) word-boundary matching in inferKind/inferEngine and never let the brief override an explicit engine. Bear in mind that several lens findings are Windows-only (platform-06/07/10, addon-05) and one (platform-12, the __pycache__) was caused by the review harness itself, so they should be deprioritised or handled as cleanup; and because the project has zero tests over its own code, each fix above should land with the first unit tests for spec.ts (inference), blender-script.ts (ast.parse of every kind x engine) and builders.ts (dimension and LOD assertions from scratchpad/critic/builders-probe.mjs).
